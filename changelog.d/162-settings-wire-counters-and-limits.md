Settings registry generations and scope revisions are now `WireCounter` newtypes, so a host can no longer stamp a value above `2^53 - 1` that its own TypeScript client refuses as an unsafe integer, and seal now refuses the two contradictory page declarations it used to accept or drop. `SettingsLimits` rejects unknown fields on the wire.

### Breaking

- **Settings counters are bounded to the JavaScript number range.** `SettingsRegistryGeneration` and `SettingsScopeRevision` wrap `longhorn_core::WireCounter`: deserializing a snapshot or command whose `generation`, `scopeRevision` or `registryGeneration` exceeds `2^53 - 1` now fails instead of producing a value the TypeScript validator rejects, `SettingsRegistryGeneration::new` and `SettingsScopeRevision::new` panic above `WireCounter::MAX`, and advancing either reports overflow there rather than at `u64::MAX`. Migration: keep any larger counter in host-owned state that never crosses the wire, construct with deserialization where the input is external, and do not catch `ScopeRevisionOverflow` as a `u64`-end case.
- **`SettingsRegistryGeneration::checked_next` returns `Result<Self, WireCounterOverflow>`.** It returned `Option<Self>`. Migration: `?` or `map_err` the error where a host advances a generation, or `.ok()` where only "advanced or not" was used.
- **`SettingsRegistryErrorCode` gains `DuplicateItem` and `InvalidPageFeatures`.** The enum is not `#[non_exhaustive]`, so a consumer's exhaustive `match` over it no longer compiles. Migration: add arms, or a wildcard arm, for the two new categories; `DuplicateItem` reports a repeated list item (page search keywords) and `InvalidPageFeatures` reports page features that contradict the writable apply units.
- **Seal rejects duplicate page search keywords.** A `SettingsPageDefinition` whose `keywords` repeat after case folding used to seal with the duplicates silently dropped; it now fails with `DuplicateItem`. Migration: remove the repeated keyword from the page declaration. The sealed snapshot for a page with distinct keywords is unchanged.
- **Reset without a reset-capable writable unit reports `InvalidPageFeatures`.** The refusal itself is unchanged — a page with `features.reset` and no writable unit declaring `reset_supported` still fails seal — but its code was `MissingReference`. Migration: match the new code where that case was caught; nothing that sealed before changes.
- **`SettingsLimits` rejects unknown fields.** A snapshot's `limits` object now accepts the twelve declared fields and nothing else, matching the TypeScript field map that already refused extra keys. Migration: send only the declared limit fields; a payload that carried extra keys was already refused by every TypeScript client.
