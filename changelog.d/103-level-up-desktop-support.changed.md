Managed-tool installs now publish a raw asset named like its binary, instead of failing on the staged file's create-new. Probes and login-shell runs get no standard input and stop after 30 seconds by default, so a hung probe cannot block an install. `CommandRunner` is a struct built with `CommandRunner::default()` or `CommandRunner::with_timeout`; the `From<RunnerError>` conversion into `InstallError` is removed, and `InstallError` and `InstallFault` now report their cause through `Error::source`. Release listings are read to 4 MiB, and a zip's declared entry count is refused before its directory is parsed. The install swap renames the verified candidate into place rather than copying it. PATH lookup names follow the managed-name rule (ASCII letters, digits, `.`, `_`, `-`, `+`, no leading dot). Browser URL error indices are offsets into the whole URL for `http://` as well as `https://`, and for `https` a backslash ends the host, as it does for loopback, and cannot hide credentials from the `@` rule. The browser callback survives a closed tab after a valid redirect. The real-keychain credential tests run only with the `real-keychain-tests` feature. Storage layout: `encode_locator` returns a `Result` and refuses a non-UTF-8 explicit root, and `locator_matches` returns the new `StorageLocatorError` instead of a string; `longhorn-config` maps both. `longhorn_support_log::single_line` is public and the diagnostics bundle uses it.
