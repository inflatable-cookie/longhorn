Clone staging cleanup in `longhorn-git-workspace` is a consuming operation on the folder the creator made, and reports its failure: `create_owned_staging` returns an `OwnedStaging` handle, `OwnedStaging::path` names that one folder for `clone_into` and `rename_exclusive`, and `OwnedStaging::remove` consumes the handle and returns the operating system's error instead of dropping it. Public API break: `remove_owned_staging` is gone and `create_owned_staging` no longer returns a `PathBuf`. Consumers migrate by holding the handle and passing `staging.path()` where they passed the staging path, then calling `staging.remove()` where they called `remove_owned_staging(&staging)`. Contract 029 matches.

A GitHub device-flow `slow_down` answer now only lengthens the poll interval: the server's suggestion is adopted when it is longer than the interval in force, and the 5 s step applies otherwise, so a shorter suggestion can no longer shorten the wait.
