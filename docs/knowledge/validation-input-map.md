# Validation Input Map

[effigy.toml](../../effigy.toml) owns the selectors, QA-group members, scope
tokens and declared limits. Use `effigy --json tasks qa-groups list` to
inspect the installed catalog and the Validate section of [AGENTS.md](../../AGENTS.md)
to plan and record worker checks. [The release contract](contracts/release.md)
covers the separate [release gate configuration](../../config/release.toml).

## Scope decisions

A group runs every member once. Scope tokens describe changed inputs and
admit a declared plan. The planner still needs to judge whether the tokens
describe the whole diff and whether the declared checks prove the change.
[Effigy's bounded QA contract](https://github.com/inflatable-cookie/effigy/blob/7b11c039d75519fffb1a770eaa61ca62097665e5/docs/knowledge/contracts/051-bounded-qa-groups-contract.md)
defines the result and refusal shapes.

For ordinary scoped work, record root Cargo manifests, the root lock and
global Effigy edits as PR gap tokens (planner ruling, 2026-10-20).
Use `lint:rust` for root Cargo manifest changes alongside the affected
package group. If planning refuses solely on those global tokens, record
the refusal and plan again for the remaining mapped scope. Other
`needs_planner` reasons require a planner decision.

An opaque task-table token applies to an edit limited to one declared task
entry. Changes to an aggregate, include, QA-group definition, admission or
toolchain setting are global even if they accompany a selector edit. Effigy
matches the token supplied by the caller and does not inspect the diff for
this distinction.

Include old and new paths for moves and the old path for deletions. Inspect
staged, unstaged and relevant untracked inputs. Use the affected graph to
discover candidate dependents. It cannot establish coverage for generated,
ignored or lockfile inputs.

## Limits outside declared groups

- Rust and TypeScript workspace selectors cover dependents in their own
  workspace. Check the consumer graphs for excluded prototypes, staged
  proof consumers and dependencies that cross the language boundary.
- A generator's compile inputs and the inputs it reads to emit a contract
  can differ. Binding changes may originate in behavior, such as licence
  conformance cases, as well as in exported types. Check generated bytes
  and the consumers that read them. The full per-domain binding compile
  closure and the full agent-control release marker source set are unresolved.
- Route a proof, helper or fixture by its readers. A shared helper can
  select several proofs. Use the artifact aggregate for its member proofs
  and changes to their common inputs. A fixture or verifier with no
  identified reader has unresolved scope.
- Bounded docs checks cover their declared surfaces. Link, path and
  documented-command checks cannot establish the accuracy of a claim or
  exercise the command's behavior. Use the owning contract or proof when
  the claim changes.
- Root locks and toolchain configuration can affect every reader in their
  build lane. Workflow changes can affect tool installation, ordering and
  clean-runner behavior. Judge these against the runners and gates they
  change. A bare lock-only or toolchain-only validation result does not exist.
- Registry resolution, advisory data, installed packages and Bun link state
  come from the environment that ran the check. Group declarations alone
  carry no evidence about their current state.
- TypeScript and Svelte selectors that chain `check:bun-deps` run
  `bun install --frozen-lockfile` when dependency markers are missing, then
  recheck them. The install outcome is part of that run's environment evidence.


## Static gates

- `typescript-static` covers the three packages, repository scripts,
  agent-control proof drivers and their toolchain configuration. It runs
  TypeScript, Svelte, Oxlint, Oxfmt, Knip and the local tests. Use the
  package-specific groups for ordinary package work. Template props and
  warnings are checked by Svelte. The private ambient shim is loaded only by
  the adapter's plain TypeScript config.
- Oxlint uses Cloudflare's preset with the pinned tsgolint backend. The
  baseline records existing diagnostics by file, rule and source fingerprint.
  The gate rejects new diagnostics and asks for resolved entries to be
  removed. Rust-generated bindings use their generator's separate byte check.
- `rust-dependencies` combines Machete's root Cargo workspace inventory
  with cargo-deny's bans, licenses and sources checks. Run it locally with
  both Cargo plugins installed. The release gate also checks live RustSec
  advisories. Standalone prototypes and staged consumers have their own
  validation routes.
