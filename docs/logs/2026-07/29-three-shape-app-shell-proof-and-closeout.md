`UiPresentationProvider`. Their app frames are different consumer
compositions.

The sequence is listener registration, authoritative snapshot load,
compatibility validation, state acceptance, mounted render, then guarded host
reveal. Loading, reconnecting, unsupported, and failed states use public
Poodle status components. No renderer fallback becomes authority.

Capability examples are profile-specific:

- Bovine: core window and titlebar drag

- Loophole: base transfer, optional Surface transfer, event lifetime, and
  titlebar drag

## Payload And Authority Audit

- Poodle owns tokens, providers, components, drag interaction, and visual
  affordances.
- Longhorn owns checked state, protocol payloads, leases, target selection,
  and host commit.
- Consumers own app frames, display/window selection, panel bodies, labels,
  product policy, and capability choice.
- Native transfer payload is protocol version plus host-issued session id.
- No Poodle class, generated id, private MIME value, or source file is used.
- No panel, Surface, layout, host-binding, window, or product state enters the
  payload.
