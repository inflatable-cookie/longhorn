## Contract Decisions

- `longhorn-surfaces` is optional and binds one Surface to one distinct layout
  container
- consumers evaluate product presence predicates
- `longhorn-surfaces-config` persists a separate expected-revision domain
- duplicate copies generic Surface metadata only
- close returns cleanup intent without deleting another domain
- `longhorn-transfer` owns finite host-created sessions and complete
  replacement leases
- payloads contain only protocol version and an unguessable session id
- overlapping targets abort instead of using enumeration order
- panel transfer supports move only within one registered layout document
- whole-Surface transfer retains its layout-container binding
- empty-display provisioning uses injected policy and explicit cleanup
  receipts
